# Autonomous Network Anomaly Detection and Self Healing Firewall System

## Project Overview

This repository contains the core infrastructure, machine learning analytics, and backend API for an autonomous network security system. The system captures live network traffic, processes it through a sliding window feature extraction pipeline, and evaluates it using an Isolation Forest anomaly detection model to autonomously block malicious IP addresses.

## File Directory and System Architecture

* **api_server.py**
The central nervous system of the project. This is a FastAPI server that manages the SQLite database, receives live packet data from the sniffer nodes, and runs the continuous background loop for the Machine Learning model. It handles the initial 20 second calibration phase and the active threat monitoring.
* **analytics_engine.py**
The computational brain. This file contains the AnalyticsEngine class. It manages the mathematical sliding window logic, transforms raw packet dictionaries into statistical feature vectors using Pandas, and executes the Isolation Forest unsupervised machine learning model from Scikit Learn.
* **sniffer_node.py**
The production network sensor. This script utilizes Scapy to intercept raw packets on the host network interface. It parses the OSI Layer 3 and Layer 4 headers and transmits the structured data to the FastAPI server via HTTP POST requests. It also contains dynamic OS level firewall execution commands.
* **firewall_logs.db**
The local SQLite database automatically generated by the API server. It persistently stores all intercepted packet metadata in the traffic logs table and records any AI triggered mitigation events in the blocked ips table.
* **sniffer.py**
A legacy development file. This was the initial prototype used to test basic Scapy packet interception before the API integration was built. It is kept for reference but is not used in the active production loop.
* **test_env.py**
A diagnostic utility script. Used to verify the installation of Python libraries, Scapy, and the Npcap Windows driver. It safely lists all available network adapters to prevent interface indexing errors.
* **__pycache__**
An auto generated system folder. Python creates this directory to store compiled bytecode versions of imported modules to speed up execution times.

## Execution Pipeline

1. Start the API Server. It will initialize the database and wait for data.
2. Start the Sniffer Node. It will begin capturing packets and sending them to the API.
3. The API Server spends 20 seconds observing the incoming traffic to build a mathematical baseline specific to the current host machine.
4. Once calibrated, the AI evaluates new traffic sliding windows every second.
5. If a volumetric spike is detected, the AI flags the anomaly and logs a block command.

## Installation and Setup Guide

To run this project on your local machine, follow these steps in order.

### Prerequisites
1. **Python 3.10+** must be installed.
2. **Network Driver:** * **Windows Users:** You MUST download and install [Npcap](https://npcap.com/). During installation, ensure you check the box for *"Install Npcap in WinPcap API-compatible Mode"*.
   * **Linux Users:** No extra drivers needed, but scripts must be run with `sudo`.

### Step 1: Install Dependencies
Open your terminal, navigate to the cloned repository folder, and install the required Python libraries using the `requirements.txt` file:
```bash
pip install -r requirements.txt
```
### Step 2: Boot the AI Core (Terminal 1)
The database and AI engine must be online before any packets are captured. Open a terminal and run the API server:
```bash
python api_server.py
```
Wait until the terminal outputs "Database ready. Starting Boot Sequence..."

Note: Open your terminal as administrator.

### Step 3: Start the Network Sensor (Terminal 2)
Open a second, separate terminal as an Administrator (Windows) or root (Linux). Run the sniffer node:

```bash
python sniffer_node.py
```
* When prompted, type the Index number of your active WiFi or Ethernet connection.
* The API Server will spend 20 seconds observing your normal traffic to calibrate its AI baseline.
* Once calibration is complete, the firewall is armed and will actively block IPs that trigger volumetric anomalies.
